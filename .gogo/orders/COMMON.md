# sbnn 並列開発 — 全作業者共通の規約

あなたは tenntenn/sbnn の issue を修正する作業者です。以下は例外なく守ってください。

## リポジトリ

- 本体: `/home/user/sbnn` （ここは**触らない**。参照のみ）
- あなたの worktree: 指示文に書かれた `worktree` パス。**ここだけで作業する**
- upstream: `origin` = https://github.com/tenntenn/sbnn 、ベースは `main`

## 手順（1 issue につき 1 回まわす）

1. `mcp__github__issue_read` で issue 本文を読む（owner=tenntenn, repo=sbnn）。
   本文には再現手順・該当コード・Expected が詳しく書いてある。**必ず読んでから直す**。
2. worktree の中で、**毎回 origin/main から**ブランチを切る:
   ```bash
   cd <worktree>
   git fetch -q origin main
   git checkout -q -B gogo/issue-<N> origin/main
   ```
   （issue ごとに独立したブランチ。前の issue の変更を積み重ねない）
3. 直す。テストを足す。
4. 検証する（下の「検証」）。
5. コミットする（下の「コミット」）。
6. `git push -u origin gogo/issue-<N>`
   失敗したら 2s → 4s → 8s → 16s でリトライ。
7. `mcp__github__create_pull_request` で PR を作る（下の「PR」）。
8. 次の issue へ。**マージはしない**（メインがやる）。

## 触ってよいファイル

指示文の「担当ファイル」に書かれた範囲だけ。ここから出ない。
テストファイルとドキュメントの該当箇所は、担当ファイルに対応する分だけ触ってよい。

- **`web/dist/` は絶対にコミットしない**（ビルド成果物。メインが波ごとにまとめて再生成する）。
  `web/src` を直したら `cd web && pnpm install --frozen-lockfile --offline && pnpm run build` で
  ビルドが通ることは確認する。確認したら `git checkout -- dist` で dist を捨ててからコミットする。
- `go.mod` / `go.sum` / `Taskfile.yml` / `.github/` は、指示文で明示的に担当していない限り触らない。

## 検証（自己申告ではなく、実際に走らせた結果を報告に書く）

Go を触ったら全部:

```bash
go build ./... && go vet ./... && go test ./... && gofmt -l $(git diff --name-only origin/main -- '*.go')
```

`gofmt -l` は**何も出力しない**のが合格。web を触ったら:

```bash
cd web && pnpm install --frozen-lockfile --offline && pnpm run build
```

**テストを必ず足す。** バグ修正には、修正前に落ちて修正後に通る回帰テストを付ける。
`internal/` 配下は既存のテーブル駆動テストの書き方に合わせる。
テストが物理的に書けない場合（ブラウザでしか出ない見た目の話など）は、
なぜ書けないかを PR 本文に 1 行で書く。

## PR

- title = コミット件名と同じ
- base = `main`, head = `gogo/issue-<N>`
- body は英語で、以下を含める:
  - 何が壊れていたか（1〜2 段落）
  - `## What changed` — 変更点
  - `## Verification` — **実際に走らせたコマンドと結果**
  - `Fixes #<N>`
  - 末尾に必ず:
    ```

    ---
    _Generated by [Claude Code](https://claude.ai/code)_
    ```

## issue がおかしいと思ったとき

**無理に直さない。** 次のどれかに当たるなら、直さずに報告へ書く:

- 前提が事実と違う（コードは既にそうなっている、その関数は存在しない等）
- 再現しない
- 仕様の決めが要る（どちらの挙動が正しいか、リポジトリの中だけでは決まらない）

その場合は「なぜそう判断したか」を**コードの引用付きで**報告に書く。
issue へのコメントはメインが書くので、あなたは書かない。

## 共有リポジトリの扱い（事故が続いているので必須）

`/home/user/sbnn` は全レーンの共有リポジトリです。**ここで `git checkout` を絶対にしないこと。**
許されるのは `git fetch` と `git worktree add`（detached）だけです。

- `code-review` スキルは対象 PR を**ローカルブランチとして本体にチェックアウトして解決します**。本体で走らせると HEAD が飛び、他レーンの作業と `.gogo/orders/` が巻き添えになります。**必ず自分の worktree で走らせること。**
- 実測: 数分おきに HEAD が飛んでいます（`pr-256` / `pr-249` / `pr193-head` / `pr207` など）。
- PR の中身を読むだけなら `git show origin/<branch>:<path>` と `git grep <rev>` で足ります。checkout は要りません。

## サーバを起動するとき

- **ポートは使う前に空きを確認すること。** 別レーンのサーバを自分のものと誤認して `--shutdown` を打った事故が起きています。
- **`pgrep -f` に緩いパターン（`$S/sbnn` など）を使わないこと。他レーンのサーバまで巻き込みます。**
- `--foreground` を nohup で起動して**起動時の PID を控え、その PID だけを kill する**こと。
- scratchpad ディレクトリは他レーンと共有されています。自分が作っていないプロセスやファイルに触らないこと。
